# Recommended Tech Stack — Departmental Store ERP

For your system, I recommend ERPNext + Frappe for the business backend and Tauri + React + TypeScript for the custom Windows POS, with SQLite for offline billing and a separate cloud/mobile layer.

7\. Deployment and infrastructure

- Server OS: Ubuntu Linux or another officially supported environment
- Deployment: Frappe's supported installation or Docker deployment
- Source control: Git + GitHub
- Backups: Encrypted local and offsite backups
- Remote access: Tailscale or Cloudflare Tunnel, appropriately secured
- Monitoring: Application logs, backup status and sync health

The store's local server must keep billing operational even if the internet or cloud services are unavailable.

## 3. System architecture

Windows POS — Tauri + React + TypeScript

Billing · Barcode · Payments · Voice · Printing

Local SQLite + Outbox Sync

Cached products · Pending sales · Retry handling

Local Store Server — ERPNext + Frappe

Validated transactions · Inventory · Accounting · GST workflows

Secure Cloud Access

Owner dashboard · Mobile · Alerts · Offsite backups

The central ERP server is the authority for finalized inventory and accounting. SQLite is the durable local queue, not a separate accounting system.

## 5. Final stack decision

My recommendation is to start with these technologies and avoid adding unnecessary infrastructure:

- Backend: ERPNext + Frappe + Python + MariaDB
- Windows POS: Tauri + React + TypeScript + Rust
- Offline: SQLite + transactional outbox
- Owner dashboard: Next.js + TypeScript
- Mobile: React Native + Expo, later
- Voice: whisper.cpp or Vosk + RapidFuzz
- Deployment: Linux server + supported Frappe deployment + Git

One important distinction: do not add PostgreSQL, Redis alternatives, a separate microservice platform or a second inventory database without a specific need. ERPNext's supported deployment has its own infrastructure requirements, and the initial system should remain as simple as possible.
